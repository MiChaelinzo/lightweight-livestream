## 2. Scalability

"Scale" here means three things.

**Down to weak hardware.** The Python process is small (22.7 MB RSS after import, 52 ms import; VERIFIED on a Linux sandbox). FFmpeg dominates cost. Measured x264 veryfast 720p30 test encodes peaked at 128 to 259 MB RSS in EVIDENCE.md section 4 and 76 to 89 MB in [BENCHMARKS.md](../BENCHMARKS.md) with Gaming First thread caps. The two numbers use different settings, and neither was measured on a low-end PC. The 300 MB total target is therefore plausible at 480p to 720p with thread caps, and UNVERIFIED on real hardware.

**Up to long sessions.** History buffers are bounded (BENCHMARKS.md: no RSS growth over 1000 simulated ticks). Real multi-hour soak was not run (UNVERIFIED). Reconnect backoff is capped at 30 s (`runner.py:13`).

**Up to more features.** Features are modules with injected callables, which scales. The two missing seams are a plugin protocol and a controller API for remote control (both Roadmap). Without them, each new integration (chat, alerts, mobile) would edit core modules.

## 3. Maintainability

- Strengths: stdlib only, `dependencies = []` in `pyproject.toml`; presets are a single source exported to the web demo and checked; tests use fake clocks and fake processes; docs label verification status.
- Weaknesses: the verification table in the README is long and hand maintained; the GUI cannot be tested without a display; some thresholds are constants with no field data (stated as design choices).
- Test shape: 452 tests in 23 files under `tests/`. `tests/test_lightstream.py` is the largest. There are no golden-file tests for FFmpeg argv per profile (Roadmap).

## 4. Performance

All numbers come from [EVIDENCE.md](EVIDENCE.md) and [BENCHMARKS.md](../BENCHMARKS.md), measured on an 8 core Linux CPU sandbox. They show the cost of LightStream's own code and relative codec cost, not behavior on Tier 1 to Tier 3 PCs.

| Measure | Result | Label |
|---|---|---|
| `import lightstream.cli` | 51.5 to 52.8 ms (EVIDENCE) ; median 72.7 ms in an older bench run with a different method | VERIFIED, this machine |
| Python process peak RSS after imports | 22.7 MB | VERIFIED, this machine |
| Per-tick cost of telemetry (`/proc`) | about 110 microseconds per call | VERIFIED, this machine |
| libx264 / VP9 / AV1 CPU seconds per 10 s of 720p30 on one thread | 3.04 / 4.84 / 6.25 | VERIFIED, one sample each |
| Game FPS impact of Gaming First | not measured | UNVERIFIED |
| Hardware encoders | not measured | UNVERIFIED |

The import figures differ (52 ms against 72.7 ms) because they come from different methods and sessions (`-X importtime` cumulative against median wall time of a fresh interpreter). Do not mix them in one claim.

## 5. Security

Full review and the defect list are in [EVIDENCE.md](EVIDENCE.md) section 5. Summary: no `shell=True`, `eval`, `exec` or `pickle` in `src/` (VERIFIED by grep); the key comes from the environment or a hidden prompt; the key is redacted in logs, including the percent-encoded form (fixed in v0.10, tested); config, prefs and history are written atomically with mode 0600 on POSIX (fixed in v0.10, tested).

Open items: the key is in FFmpeg's argv and visible in the process list (limit, by design); a custom `url` stored in `config.json` can hold the key; redaction is exact match plus the encoded form; the companion token sits in the OBS browser source URL. This was a source review and not a penetration test. Hosting headers beyond `web/vercel.json` are UNVERIFIED.
